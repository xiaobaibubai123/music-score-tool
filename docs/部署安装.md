# 部署安装

本项目是**纯静态**网页应用：没有后端、没有数据库、没有构建步骤。
部署 = 把几个文件拷到网站目录。

---

## 一、环境要求

| 项目 | 要求 |
|---|---|
| 运行环境 | **任意现代浏览器**（Chrome / Edge / Firefox / Safari） |
| 服务端 | **什么都不需要** —— nginx、Apache、对象存储、静态托管平台都行 |
| Node.js | **只有本机预览和打包时需要**（任意 LTS 版本，v16+ 即可）。生产环境不需要 Node |
| 构建步骤 | **没有** —— 直接用现成的 HTML |

---

## 二、本地运行（最快上手）

```bash
node serve.js                  # 默认 http://localhost:8081/
```

`serve.js` 是一个零依赖的静态服务器，内置：

- **gzip / brotli 压缩** —— `Tone.js` 从 341 KB 压到约 73 KB
- **分级缓存** —— `vendor/`、`assets/` 一年强缓存，HTML 每次校验（保证你一改就生效）
- **ETag / 304** —— 回访只传几百字节

访问：

| 页面 | 地址 |
|---|---|
| 乐谱工作台（写谱 / 试听 / 导出） | http://localhost:8081/ |
| 演奏录音页（自己弹 → 自动变乐谱） | http://localhost:8081/record.html |

> **必须点一下页面才能出声** —— 浏览器自动播放策略要求先有一次用户点击。
> 页面顶部会有提示，不是 bug。

其他用法：

```bash
node serve.js 9000              # 换端口
node serve.js 9000 dist         # 发布指定目录（相对当前所在目录）
node serve.js 9000 ../dist      # 也可以（相对当前工作目录解析）
```

## 三、打包成部署包

```bash
node build-dist.js
```

产出 `dist/`：

```
dist/
├── index.html          乐谱工作台（入口）
├── record.html         演奏录音页（入口）
├── src/
│   ├── parser.js        10 KB  乐谱 DSL 解析器（页面和测试共用同一份）
│   ├── recorder.js       9 KB  录音→乐谱的量化与排版（页面和测试共用同一份）
│   ├── keymap.js         7 KB  键位预设与 JSON 解析（页面和测试共用同一份）
│   └── audio.js          4 KB  钢琴音源（两个页面共用同一份）
├── config/
│   └── keymap.json       1 KB  ← 想换键盘键位就改这个文件
├── vendor/
│   ├── Tone.js         341 KB  音频引擎
│   ├── Midi.js          32 KB  MIDI 解析 / 写入
│   ├── lame.min.js     152 KB  MP3 编码器
│   └── piano/*.mp3     1.9 MB  钢琴采样 30 个（Salamander Grand Piano）
└── assets/
    └── demo.mid         17 KB  内置示例曲
```

**合计约 2.6 MB，41 个文件。** 全部使用相对路径，放根目录或任意子目录都能用。
`build-dist.js` 打包完还会逐条检查页面里引用的东西（`src/*.js`、`config/keymap.json`、
`vendor/*`）是不是都真的进了 dist —— 挪目录最容易漏的就是这个。

> **关于那 1.9 MB 的钢琴采样**：只在**第一次点「▶ 试听」时**才开始下载（不是首屏加载），
> 之后走浏览器强缓存，回访不再下载。这 1.9 MB 换来的是真实钢琴音色——
> 之前用合成器时右手高音区有明显的电子味。
>
> 想省掉这 1.9 MB：直接删掉 `vendor/piano/` 整个目录。
> 程序会自动退回内置合成器音色，功能完全不受影响（这条降级路径有测试覆盖）。
> 代价就是音色没那么真实。`build-dist.js` 在采样少于 30 个时会拒绝打包，
> 所以删完记得连那条检查一起改，或者干脆用 `FILES`/`DIRS` 只挑需要的文件手动部署。

打包脚本会做三项安全检查，不通过会直接报错退出：

1. 页面里若出现以 `/` 开头的**绝对资源路径** → 报错（避免部署到子目录后 404）
2. `vendor/`、`assets/` 是否齐全
3. 钢琴采样是否为完整的 30 个（少一个就会有音只能靠邻近采样硬拉，听起来发怪）

## 四、部署到线上

### 4.1 静态托管平台

把 `dist/` 里的**全部内容**上传到网站根目录即可：

| 平台 | 做法 |
|---|---|
| **GitHub Pages** | 把 `dist/` 内容推到 `gh-pages` 分支。放在子目录（`user.github.io/仓库名/`）也能用，已实测 |
| **Cloudflare Pages / Netlify / Vercel** | 拖拽 `dist/` 上传，构建命令留空，输出目录填 `dist` |
| **对象存储**（OSS / COS / S3） | 上传后开启静态网站托管 |
| **纯手写 HTML 的站** | 直接建目录放进去，例如 `tools/music/` |

### 4.2 nginx（自己的服务器）

```nginx
server {
    listen 443 ssl;
    server_name music.example.com;
    root /var/www/music;          # 把 dist/ 里的内容放到这里
    index index.html;

    # ① 压缩：Tone.js 从 341 KB 压到约 73 KB，这是省带宽最大的一环
    gzip on;
    gzip_comp_level 6;
    gzip_min_length 1024;
    gzip_vary on;
    gzip_types text/html text/css text/javascript application/javascript
               application/json image/svg+xml;
    # nginx 默认就会发 ETag / Last-Modified 并自动处理 304，不用额外配置

    # ② 库文件长期强缓存（内容基本不变；换库版本时改 HTML 里的 ?v=N）
    location /vendor/ {
        expires 1y;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, max-age=2592000";
    }

    # ③ HTML 每次校验，保证你一改别人就立刻能看到（没变时 nginx 自动回 304）
    location ~ \.html$ {
        add_header Cache-Control "no-cache";
    }

    location / { try_files $uri $uri/ =404; }
}
```

配上 HTTPS（certbot 一条命令）后，Web MIDI 就能用了。

## 五、嵌入个人网站

### 5.1 目录规划

```
你的网站根目录/
├── index.html
├── tools.html              工具栏目页     ← 在这里加入口
└── tools/
    └── music/              ← 把 dist/ 里全部内容放这里
        ├── index.html
        ├── record.html
        ├── src/            ← 别漏传、别改名
        ├── config/         ← keymap.json 在这里
        ├── vendor/
        └── assets/
```

**先确认 `/tools/music/` 能直接访问**，再做嵌入。

### 5.2 方案 A：工具卡片 + 独立页面（最推荐）

最省心、手机体验最好：

```html
<a class="tool-card" href="/tools/music/">
  <div class="tool-card__icon">🎼</div>
  <h3>在线乐谱工具</h3>
  <p>用文字写乐谱，立刻听到效果。支持导出 MIDI / MP3。</p>
</a>
```

### 5.3 方案 B：工具页内嵌 iframe

```html
<section class="tool-embed">
  <h2>🎼 在线乐谱工具</h2>
  <p>用文字写乐谱，立刻听到效果。支持导出 MIDI / MP3。</p>

  <iframe
    src="/tools/music/"
    style="width:100%;height:900px;border:0;border-radius:12px"
    allow="midi"
    loading="lazy"
    title="Web 电子乐谱 · 乐谱工作台"></iframe>

  <p style="margin-top:8px;font-size:14px">
    <a href="/tools/music/" target="_blank" rel="noopener">
      在新窗口打开完整版 ↗
    </a>
  </p>
</section>
```

三个属性别省：

- `allow="midi"` —— 将来接真实 MIDI 键盘要用
- `loading="lazy"` —— 滚到才加载，不影响你网站首屏速度
- `title="..."` —— 无障碍需要

**「在新窗口打开」这个链接建议保留** —— 手机上 iframe 体验不如全屏。

> 演奏录音页用同样的方式嵌入，把 `src` 换成 `/tools/music/record.html` 即可
> （它体量更大，建议给到 `height:1100px`）。两个页面互相有入口，不需要都嵌。
> 录音页的琴键支持触摸，手机上可以直接弹。

> ⚠️ **不要给 iframe 加 `sandbox` 属性**（除非你加上 `allow-downloads`），
> 否则导出 MIDI / MP3 的下载会被浏览器拦掉。

### 5.4 主题协调

工具是**深色主题**（背景 `#12141a`）。如果你的网站是浅色的，两个办法：

**办法一（推荐）**：改两个页面 `<style>` 里的 `:root` 变量：

```css
:root{
  --bg:#ffffff; --panel:#f7f8fa; --line:#e3e6ec; --fg:#1f2430; --dim:#6b7280;
  --accent:#2563eb; --ok:#16a34a; --bad:#dc2626; --warn:#d97706;
}
```

**办法二**：接受深色，把它做成"故意的一块深色面板"，加圆角和内边距。

## 六、实际网络开销（实测）

用 Chrome + CDP Network 域逐请求统计 `encodedDataLength` 得到。「再次访问」已开启正确缓存策略。

| 场景 | 传输量 | 请求数 |
|---|---|---|
| 首次打开页面（空缓存） | 152 KB | 4 |
| 再次打开页面（有缓存） | **0.2 KB** | 4 |
| **第一次点「▶ 试听」**（额外加载钢琴采样） | **1.9 MB** | 30 |
| 之后每次播放 | **0 KB**（采样走强缓存） | 0 |

首次打开页面的 152 KB 里，Tone.js 73 KB、MP3 编码器 51 KB、MIDI 解析 9 KB、页面本身 18 KB。
钢琴采样**不在首屏加载**，而是等第一次点播放才下载，所以单纯浏览页面不会吃掉那 1.9 MB。

**结论：**

- 服务器端**不做任何计算** —— 没有 PHP/Node 执行、没有数据库、没有会话，每个请求只是读文件发字节
- 真正的成本是**带宽**，由「压缩」和「缓存」两个开关决定：
  - 不压缩：首屏 341 KB+（光 Tone.js 一项）
  - 只压缩：152 KB
  - 压缩 + 缓存：再次访问 0.2 KB
  - 钢琴采样 1.9 MB 只在首次播放时付一次，之后走 `vendor/` 的一年强缓存
- **导出 MP3 的算力在访问者机器上**：约 1 秒音频需要 0.4 秒渲染+编码，服务器零参与

## 七、排错

### 7.1 没有声音

1. **点一下页面** —— 浏览器要求先有一次用户点击才能出声（页面顶部有提示）
2. 检查系统音量和浏览器标签页是否被静音（标签上会有一个小喇叭图标）
3. 按 F12 → Console 看有没有红色报错

### 7.2 点了「导出 .mp3」但找不到文件

这是反馈最多的问题，按顺序排查：

1. **按钮上有没有进度数字？** 导出分两步：先 `🎵 渲染中…`，然后 `🎵 编码 0% → 100%`。
   **看到数字在涨就说明它在工作，别关页面**。约 1 秒音频要 0.4 秒，93 秒的曲子约需 40 秒。
2. **等状态栏出现绿色的「✅ 已导出 MP3：文件名」** —— 这时才真的开始下载。
3. **按 `Ctrl + J`** 打开浏览器下载页，文件在最上面，右边有「在文件夹中显示」。
4. 文件默认落在**浏览器的默认下载目录**（Windows 一般是 `C:\Users\<你>\Downloads`）。
   网页本身无法决定下载位置。
5. 如果状态栏出现**红色 `❌ 导出 MP3 失败`**，把后面的文字发出来。
6. **先拿短曲子试**：工作台点「载入示例」（小星星，约 10 秒），导出只要几秒。
   能成功说明机制没问题，再去导长曲子。

### 7.3 部署到子目录后页面打不开 / 样式丢失

`build-dist.js` 已经会拦下绝对路径。如果还有问题：

- F12 → Network 看哪个资源 404，通常是 `vendor/` 或 `assets/` 漏传了
- 确认目录名没被改过

### 7.4 导出 MP3 时页面卡住

编码在主线程跑（会分块让出，但长曲子仍可能有短暂卡顿）。
如果经常导长曲子，可以：

- 把码率从 192 降到 128（`index.html` 里 `encodeMp3(ab, 192)`）
- 或者用 `.mid` 导出，在 MuseScore 等软件里导出音频

### 7.5 Web MIDI 键盘连不上

Web MIDI 需要**安全上下文**：`https://` 或 `localhost`。
`http://` 的内网 IP 下浏览器会禁用该接口 —— 键盘弹奏、MIDI 文件载入、自动演奏都不受影响。

## 八、回归测试

```bash
cd tools
npm install            # 装 puppeteer-core / @tonejs/midi / lamejs
npm test               # 跑全部七套
```

单独跑：

```bash
node parser-test.js      # 解析器 + MIDI 导出 单元测试
node recorder-test.js    # 录音→乐谱 单元测试（含 400 组随机演奏的模糊测试）
node keymap-test.js      # 键位表 单元测试（重点测"用户写错了会怎样"）
node verify-workbench.js # 工作台 端到端（56 项）
node verify-record.js    # 演奏录音页 端到端（59 项）
node verify-embed.js     # iframe 嵌入 端到端（15 项）
node verify-mp3.js       # MP3 导出 端到端（12 项）
node verify-timbre.js    # 钢琴音源 端到端（13 项）
```

`recorder-test.js` 里有 400 组确定性随机演奏（固定种子，失败可复现），
逐个音比对"弹进去的"和"从生成的乐谱里读回来的"起点、终点、音高、所在轨道。
这套测试就是这么抓出过三个真 bug 的：落在别的音中间的短音被整个吃掉、
1/32 网格下 0.375 拍被四舍五入成 0.38 导致每小节多 0.01 拍、
以及暂停期间的空档被算进了乐谱。

`keymap-test.js` 重点测的是**用户改错键位以后会怎样** ——
`"keya"`（大小写写错，`e.key` 思维）、`"C99"`（音名解析会算出 MIDI 1200）、
不存在的 code、整个 JSON 语法错，都必须给出能看懂的提示，而不是静静地少一半键。
另外它专门测了**冲突**：同一个键绑给两个音能不能被认出来（这是按键的人自己绝对发现不了的）。
它还断言仓库里的 `config/keymap.json` 和页面内置的默认键位完全一致，
免得出现"我明明改了 config/keymap.json 却没生效"这种最难查的问题。

测试用**真实浏览器**驱动，通过 `chrome.js` 自动查找 Chrome / Edge，
找不到时用环境变量指定：

```bash
CHROME_PATH=/usr/bin/google-chrome npm test        # Linux/macOS
set CHROME_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe   # Windows
```

**验证部署产物本身**（而不是开发目录）：

```bash
node serve.js 8082 dist
BASE_URL=http://localhost:8082 node verify-workbench.js   # Linux/macOS
$env:BASE_URL="http://localhost:8082"; node verify-workbench.js  # Windows PowerShell
```

### 覆盖范围

- 电脑键盘发声、八度切换、真实浏览器键盘输入进 iframe
- 演奏录音页：键盘/鼠标弹奏、开始/暂停/继续/结束、**暂停的时长不会被算进乐谱**、
  撤销、清空、生成的乐谱能被工作台直接打开
- 键位：钢琴一次显示一组（C4–C5，13 键）、◀ 降一组 / 升一组 ▶ 换音区且音区标签跟着走、
  默认"键盘主键区"排法、切预设、在页面上点着改（改绑 / 抢键 / 删除）、
  **冲突键位标红且能一键修复**、导入自定义键位 JSON（真的走文件选择框）、
  导出的 JSON 能原样再导入
- 播放 / 暂停 / 继续 / 停止 / 变速，循环回卷
- 上传 `.mid` / `.json`、导出 `.json` 再读回的往返一致性
- 中文曲名与轨道名的 UTF-8 正确落盘
- 语法错误带行号、点击跳转、拍数校验警告
- 刷新后作品仍在（localStorage）
- 跨页跳转、iframe 内真实键盘输入、窄 iframe 下键盘不裁切
- 导出 MP3 后用 `decodeAudioData` **真实解码**，校验时长 / 声道 / 峰值 / RMS

## 九、更新与维护

| 想改什么 | 改哪里 |
|---|---|
| 页面外观、文字、按钮 | `index.html`（工作台）/ `record.html`（录音页） |
| 内置示例曲目 | `index.html` 里的 `DEMOS` 对象 |
| 语法规则 | `src/parser.js` 的 `parseScore()`（**两个页面和测试共用这一份**） |
| 录音怎么量化、怎么排成小节 | `src/recorder.js`（页面和测试共用这一份） |
| 键盘键位 | `config/keymap.json`（音符当 key、按键当 value，改完刷新即生效）；也能在页面上点着改 |
| 键位预设和 JSON 校验 | `src/keymap.js`（页面和测试共用这一份） |
| 音色（采样目录、音量、混响、兜底合成器） | `src/audio.js` 的 `PIANO`（**两个页面共用这一份**） |
| MP3 码率 | `encodeMp3(ab, 192)` |
| 不要 MP3 功能 | 删掉 `vendor/lame.min.js` 和引入它的那行 `<script>` |
| 内置演示 MIDI | 替换 `assets/demo.mid` |

**改完的流程：**

```bash
node build-dist.js     # 重新打包
# 重新上传 dist/
```

如果替换了 `vendor/` 里的库，记得把 HTML 里的 `?v=2` 改成 `?v=3` ——
`vendor/` 是一年强缓存的，不改版本号老访客会一直用旧文件。
